# Day 07 – Linux File System Hierarchy & Scenario-Based Practice

# Part 1 – Linux File System Hierarchy

---

## 1. / (Root Directory)

### Purpose
- The root directory is the starting point of the Linux file system.
- Every file and directory exists under `/`.

### Command

```bash
ls -l /
```

### Example Output

```text
bin
boot
dev
etc
home
opt
root
tmp
usr
var
```

### I would use this when...
I need to navigate the Linux file system or locate important directories.

---

## 2. /home

### Purpose
- Stores home directories of normal users.
- Every user gets their own personal directory here.

### Command

```bash
ls -l /home
```

### Example Output

```text
ubuntu
john
```

### I would use this when...
I need to access user files or troubleshoot user-specific issues.

---

## 3. /root

### Purpose
- Home directory of the root (administrator) user.
- Accessible only by the root user.

### Command

```bash
ls -l /root
```

### Example Output

```text
scripts
backup.sh
```

### I would use this when...
Managing administrative files or scripts.

---

## 4. /etc

### Purpose
- Contains system-wide configuration files.
- Most Linux service configurations are stored here.

### Command

```bash
ls -l /etc
```

### Example Output

```text
hosts
hostname
passwd
ssh
systemd
```

### I would use this when...
Editing or checking Linux configuration files.

---

## 5. /var/log

### Purpose
- Stores log files generated by the operating system and applications.
- One of the most important directories for troubleshooting.

### Command

```bash
ls -l /var/log
```

### Example Output

```text
syslog
auth.log
kern.log
journal
```

### I would use this when...
Checking logs to diagnose application or system issues.

---

## 6. /tmp

### Purpose
- Stores temporary files.
- Files may be deleted automatically after reboot.

### Command

```bash
ls -l /tmp
```

### Example Output

```text
systemd-private
tempfile.txt
```

### I would use this when...
Creating temporary files during testing.

---

## 7. /bin

### Purpose
- Contains essential Linux commands required during boot and recovery.

### Command

```bash
ls -l /bin
```

### Example Output

```text
bash
cp
mv
ls
cat
```

### I would use this when...
Finding essential Linux utilities.

---

## 8. /usr/bin

### Purpose
- Stores user-level executable programs.

### Command

```bash
ls -l /usr/bin
```

### Example Output

```text
python3
git
vim
docker
```

### I would use this when...
Running installed software and utilities.

---

## 9. /opt

### Purpose
- Stores optional or third-party software.

### Command

```bash
ls -l /opt
```

### Example Output

```text
google
microsoft
```

### I would use this when...
Installing or managing third-party applications.

# Hands-on Practice

## Find the Largest Log Files

```bash
du -sh /var/log/* 2>/dev/null | sort -h | tail -5
```

### Observation

Displays the five largest log directories/files.

---

## Check Hostname

```bash
cat /etc/hostname
```

### Observation

Displays the hostname of the Linux machine.

---

## Check Home Directory

```bash
ls -la ~
```

### Observation

Lists all files including hidden files in the home directory.

# Part 2 – Scenario-Based Practice

---

# Scenario 1 – Service Not Starting

## Step 1

```bash
systemctl status myapp
```

**Why?**

Check whether the service is running, failed, or stopped.

---

## Step 2

```bash
journalctl -u myapp -n 50
```

**Why?**

Read the latest logs to identify errors.

---

## Step 3

```bash
systemctl is-enabled myapp
```

**Why?**

Verify whether the service starts automatically after reboot.

---

## Step 4

```bash
systemctl restart myapp
```

**Why?**

Restart the service after fixing the issue.

---

# Scenario 2 – High CPU Usage

## Step 1

```bash
top
```

**Why?**

Monitor CPU usage in real time.

---

## Step 2

```bash
ps aux --sort=-%cpu | head -10
```

**Why?**

Display the top CPU-consuming processes.

---

## Step 3

```bash
ps -fp <PID>
```

**Why?**

Get detailed information about the process.

---

## Step 4

```bash
kill <PID>
```

**Why?**

Terminate the problematic process if required.

---

# Scenario 3 – Finding Docker Logs

## Step 1

```bash
systemctl status docker
```

**Why?**

Verify that Docker is running.

---

## Step 2

```bash
journalctl -u docker -n 50
```

**Why?**

View the latest Docker logs.

---

## Step 3

```bash
journalctl -u docker -f
```

**Why?**

Follow Docker logs in real time.

---

# Scenario 4 – Permission Denied

## Step 1

```bash
ls -l /home/user/backup.sh
```

**Why?**

Check the current permissions.

---

## Step 2

```bash
chmod +x /home/user/backup.sh
```

**Why?**

Add execute permission.

---

## Step 3

```bash
ls -l /home/user/backup.sh
```

**Why?**

Verify that execute permission was added.

---

## Step 4

```bash
./backup.sh
```

**Why?**

Execute the script and confirm the issue is resolved.

---

# Key Takeaways

- The Linux file system is organized into directories with specific purposes.
- `/etc` stores configuration files.
- `/var/log` is the first place to check during troubleshooting.
- `systemctl` and `journalctl` are essential for diagnosing services.
- `top` and `ps` help identify high CPU usage.
- `chmod` resolves execute permission issues.
